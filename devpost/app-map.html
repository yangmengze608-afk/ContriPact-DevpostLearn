ContriPact · take-home map

Rules → evidence → proposal → objection.

ContriPact is a local proof of concept for making team reward allocation inspectable and contestable. The AI does not decide objective fairness: it maps supplied competition rules and evidence into a validated proposal, then the team decides whether to accept it.

Public release snapshotReact + ViteExpressOllama / Spark-X2.5-4BProcess-memory cache

One real action through the app

Follow the After → O2 objection path. The browser requests analysis; the server replaces untrusted browser facts with the canonical prepared case; the provider asks Spark for structured JSON; validators reject unsupported or untraceable claims; only validated results are cached and rendered.

Reference route — 3 useful stops

1. Visible action / statesrc/components/workspace/Workspace.tsx — search runAfterAnalysis and runObjection. This is where the UI decides when After can run, when O2 can be checked, and when a team can accept the proposal.
2. Trust boundary / cacheserver/routes/analysis.ts — search router.post('/after', router.post('/objection', and cachedAnalysis. The route validates the scenario, uses canonical server-side facts, requires the current validated After result before O2, and caches only successful results.
3. Model contract / rejection rulesserver/ai/ollamaSpark.ts + server/ai/validate.ts — search analyzeAfter, checkObjection, validateAfter, and validateObjection. The model can propose; these validators decide whether that proposal is structurally and evidentially acceptable to the product.

A practice to reuse

Freeze the model's fact contract before you tune the model. During this build, the product path and model gate once produced different valid proposals even with deterministic sampling. The difference was not temperature: the product prompt had compressed criteria to a different input shape. Aligning both paths to the same canonical id + name + weight contract removed that source of drift. The shipping audit later reinforced the same lesson when the prepared rubric itself had to be corrected to the current official criteria.

Reusable pattern: canonical input → structured schema → cross-field validator → observed repeated run. On another AI product, use the same chain before claiming reproducibility or grounding.

Evidence anchors

devpost/checklist.md → Revisions records the prompt-contract correction. server/ai/prompts.ts constructs the canonical request. server/ai/validate.ts rejects outputs that violate product invariants. The build verification observed validated cache reuse; exact proposal numbers are treated as model outputs tied to the current rubric, not hard-coded product facts.

Run it again

  1. Use Node 24 LTS (.nvmrc is included).
  2. Make sure Ollama is running and the configured Spark model is available.
  3. From the repo root: npm install, then npm run dev.
  4. Open http://127.0.0.1:5173.
  5. For a recording session, keep the server running and execute npm run warm once. Only real validated inference is cached.

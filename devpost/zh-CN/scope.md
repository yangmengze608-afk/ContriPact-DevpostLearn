# ContriPact — Build With AI POC（中文版）

一句话：一个由 AI 辅助的团队贡献治理 POC，让小团队在比赛开始前先约定“什么算高价值贡献”，或者在比赛结束后基于规则与证据评估实际贡献，从而避免成员因为面子、关系或操守而难以直接争论“谁应该拿更多”。

## 独特核心
真正的问题不是数学，而是社交压力。

现实里，即使团队成员都知道贡献并不完全相同，大家也常常不好意思直接说“我的贡献更大”或“你的贡献没那么关键”，因为这会伤害关系、显得计较，甚至违背大家对团队合作的礼貌与操守预期。结果往往是默认平均分，或者交给队长做一个大家都不太敢质疑的判断。

ContriPact 希望让 AI 充当一个相对中立的第三方，评估的是**某项贡献对比赛结果的重要性**，而不是宣称自己拥有“公平”的最终答案。

产品天然有两个时间点：

- **项目开始前**：AI 先阅读比赛规则与评审标准，判断哪些任务最可能形成高贡献点，生成贡献规划，并让全队在开工前确认“什么工作应该被认为更关键”。
- **项目结束后**：AI 阅读同一套比赛规则，再结合每位成员真实完成的工作与证据，评估哪些贡献真正关键、为什么关键，并给出贡献判断与奖金分配建议，再征求团队同意。

如果成员提出异议，AI 会对理由做基础判断：这个异议是否真的和比赛规则、实际证据或事先同意的贡献标准有关。最终决定仍然由团队确认，而不是由 AI 强制裁决。

## 为谁服务
面向要共享奖金或其他可分配奖励的小型比赛团队、黑客松团队、科研合作组、社团项目或 Side Project 团队。

POC 的具体场景是一支 4 人比赛队伍。他们希望奖金能体现贡献差异，但又不希望靠成员之间互相争论“谁更重要”来解决。

## 核心循环
### 项目开始前模式
1. 团队载入一份预设的比赛规则与评审标准。
2. AI 提取真正影响比赛结果的核心评审维度。
3. AI 把计划中的任务映射到这些评审维度，标出最可能形成高贡献的工作。
4. 团队查看这份贡献规划，并选择同意或提出有理由的异议。
5. 最终确认的贡献地图成为比赛结束后评估的参照。

### 项目结束后模式
1. 团队载入相同比赛规则，并加入每位成员的实际工作与证据。
2. AI 按比赛规则和事先约定的贡献地图评估每项工作。
3. AI 标出最强的贡献点，并解释为什么这些工作对比赛结果重要。
4. AI 根据贡献判断给出奖金分配建议。
5. 任意成员可以提出异议并说明理由。
6. AI 检查该理由是否和规则/证据真正相关，并据此调整或解释原推荐。
7. 团队确认最终方案。

## 灵感与产品气质
延续 ContriPact 的产品气质：冷静、克制、重证据、像一个中立的治理工具，而不是“AI 判官”游戏，也不是金融交易看板。

界面最重要的关系是让用户一眼看到：

**比赛规则 → 贡献价值 → 奖金建议**

## 为什么这对我重要
这次比赛版不只是为了再做一个能跑的网站，而是拿 ContriPact 当练习载体，完整经历一次规范的开发流程：Scope → PRD → Spec → Build → Verify → Ship。

因为核心产品想法已经存在，所以这一次更适合把注意力放在“怎样把想法变成一个边界清楚、可验证、可交付的 POC”。

## 什么叫做“做成了”
评委应该能在大约 60 秒内理解产品价值：

- 看到一个 4 人团队和一份真实感很强的比赛规则；
- 系统先指出最重要的评审标准；
- 在 **开始前** 模式里，AI 判断哪些计划任务最可能产生高价值贡献，并让团队确认；
- 在 **结束后** 模式里，AI 读取真实贡献证据，标出最关键的贡献点并说明理由；
- 系统根据这些判断给出 ¥12,000 奖金分配建议；
- 一名成员提出异议；
- 系统判断这个异议是否真的受到规则或证据支持，并调整或解释推荐；
- 最终团队确认方案。

真正的“啊，这东西有用”时刻，不是看到 AI 算出一个百分比，而是看到 AI 能说清：

**“为什么这项工作在这场比赛里更重要。”**

这样团队成员就不需要亲自说“你贡献太少了”。

## POC 边界
这一版只做：
- 一个预设的 4 人比赛场景；
- 一份预设比赛规则/评审标准；
- **开始前 / 结束后** 两种模式；
- 开始前有预设任务；
- 结束后有预设贡献记录与证据；
- 一次 AI 辅助的“规则 → 贡献”分析；
- 一份贡献价值判断；
- 一个 ¥12,000 现金奖励分配建议；
- 一次异议与基础理由判断；
- 一个最终确认状态；
- 全流程可以在短视频和公开 GitHub 仓库中演示。

核心必须是真的：奖金推荐必须能明确追溯到页面里展示的比赛规则与贡献证据，而不能只是装饰性的 AI 文案。

## 以后再做

- 真实多用户登录与邀请；
- 项目进行中的实时贡献记录；
- Peer Review 与 GitHub / Docs / Figma 等证据接入；
- 持久化项目与审计日志；
- 多轮异议与修改；
- 可配置奖金政策；
- 实物奖品分配；
- 正式模型评估与偏差监控。

## 明确砍掉
- **完整账号系统**：不能帮助证明“规则 → 贡献评估”这个核心。
- **生产数据库与 Supabase**：这次用预设案例就足够。
- **多人浏览器邀请链路**：基础设施不是这次要验证的核心。
- **持续贡献追踪**：以后重要，但本 POC 不必做。
- **支持所有比赛格式的文件解析**：一份预设比赛规则就能验证核心逻辑。
- **让 AI 最终裁定什么叫公平**：AI 判断贡献价值并提出建议，最后仍由团队确认。
- **计费、分析后台、管理员等生产功能**：不属于 2–4 小时学习型 POC。
